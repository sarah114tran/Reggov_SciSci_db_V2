# Reggov SciSci DB

A self-contained ETL pipeline that builds a local SQLite database of federal
regulatory dockets, public comments, their citations, and author/organization
classifications. This repo contains everything needed to build the database
from scratch: the processed input data files and the scripts that load them.

It's a trimmed export from a larger working repo — only the final-stage
loaders and their direct inputs are included here, not the upstream scraping
and classification pipelines that originally produced those inputs.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Build the database

```bash
python main.py
```

This creates `dockets.db` (SQLite) in the repo root. The script is
idempotent — all row IDs are deterministic UUIDs derived from natural keys
(see `utils.py`), so re-running it won't create duplicates.

## Validate

```bash
python validate.py
```

> **Note:** `validate.py` currently checks table names (`federal_docket`,
> `comment_paragraphs`, `citation_metadata`, ...) that predate the schema in
> `models.py` (which uses `agency_docket`, `public_comments`,
> `comment_citations`, etc.). It needs to be updated to match the current
> schema before it will run correctly.

## Pipeline

`main.py` orchestrates the load in this order:

| Step | Loader | Reads |
|---|---|---|
| FR dockets | `loaders/docket.py` | `data/docket_metadata.json` |
| Comments | `loaders/comments.py` | `data/normalized_comment_metadata.json` (+ `data/filtered_comment_metadata.json` for organization_root_name) |
| Citations | `loaders/gemini_citations.py` | `data/citation_data/extracted_citations/final_citation_data.json` |
| Citation classification backfill | `loaders/citation_classification_backfill.py` | `data/citation_data/claude_classified_citations_unverified.json` |
| Citation reclassification (high-confidence) | `loaders/citation_reclassification.py` | `data/citation_reclassification/*.csv`, `merged_tiers_openalex_matched.json` |
| RFI self-reference cleanup | `loaders/rfi_self_reference_cleanup.py` | `data/rfi_self_reference_citation_ids.csv` |
| Educational-resource reclassification | `loaders/edu_resources_reclassification.py` | `data/citation_reclassification/edu_resources_classified.json` |
| Resolved OpenAlex works | `loaders/citation_resolved_works.py` | `data/citation_data/citation_resolved_works_normalized.json` |
| Comment authorship backfill | `loaders/comment_authorship.py` | `data/comment_authorship.json` |
| Per-author rows | `loaders/comment_authors.py` | `data/processed_authorship.json` |
| NAICS / commenter classification | `loaders/naics_classification.py` | `data/processed_authorship_with_naics.json`, `data/unique_orgs_with_naics.json` |
| Org classification corrections | `loaders/additional_org_classification.py` | `data/additional_classified_orgs_final.csv` |
| Individual reclassification (2nd pass) | `loaders/individual_reclassification.py` | `data/classified_all.json` |

`data/rfi_self_reference_citation_ids.csv` is a fixed, reviewed list of 408
`citation_id`s that are self-references to the RFI/docket notice a comment
was itself filed under (a link to the comment's own federalregister.gov/
regulations.gov page, a bare "XX Fed. Reg. NNNNN" citation, a NIST
publication ID, or an opening-sentence/title-overlap match — see
`loaders/rfi_self_reference_filter.py`) rather than citations to external
evidence. `final_citation_data.json` still contains these rows, so this
step deletes them by exact ID after loading.

The exclusion list was generated by running
`loaders/rfi_self_reference_filter.py` — a per-docket signal-based
classifier that pulls each comment's own docket identity (document number,
FR citation, NIST ID, distinctive title words, publication date) from
`agency_docket` rather than using any single hardcoded rule — against this
repo's data, then reviewing every flagged entry. That run flags 408
entries; all 408 have now been reviewed and confirmed (396 in an initial
pass, plus 12 more from one docket — "Advancing Privacy-Enhancing
Technologies", doc 2022-12432 — that the original cleanup evidently never
covered). With a reproducible build (deterministic citation_ids),
re-running the build always reproduces the same result.

`data/citation_data/citation_resolved_works_normalized.json` is generated
from `data/citation_reclassification/merged_tiers_openalex_matched.json` by
the source repo's `citations/citation_parsing/build_resolved_works_input.py`
— it flattens two different match-record shapes (direct DOI/arXiv/Crossref
matches, which carry a `status` field, and title-search-tier matches, which
instead signal a confirmed match via `match_reason` and never set `status`)
into one normalized row per resolved citation. Checking only `status` on the
raw `merged_tiers_openalex_matched.json` undercounts matches substantially
(it misses the entire title-search tier) — use `build_resolved_works_input.py`
or treat this normalized file as the source of truth for what's actually
matched, not `status` on the raw file.

`data/first_author_propagation_review.json` is an **output**, not an input —
`main.py` writes it during the NAICS step as a review file for ambiguous
multi-author organization propagation.

`data/raw_predictions/` (the two large `.jsonl` files) are not currently
consumed by any loader in this pipeline — they're raw model-prediction
outputs from an earlier stage, included for reference.
